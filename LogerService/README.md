# LogerService

Сервис хранения логов. Формат входящего сообщения основан на доменной сущности
[`LogItem`](LogerService.Domain/Entities/LogItem.cs) и перечислении
[`LogLevel`](LogerService.Domain/Enums/LogLevel.cs).

### Поля тела сообщения

| Поле JSON     | Поле `LogItem` | Тип в JSON            | Обязательное | Описание                                                                                                                                                                                                         |
| ------------- | -------------- | --------------------- | ------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `eventId`     | `EventId`      | string (UUID)         | Да           | Уникальный идентификатор события, созданный отправителем. Формат: `xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx`. Нулевой UUID недопустим. При повторной отправке того же события идентификатор сохраняется.             |
| `traceId`     | `TraceId`      | string (UUID)         | Да           | Общий идентификатор действия или цепочки связанных событий. Формат: `xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx`. Нулевой UUID недопустим. Повторяется у всех событий одного действия, в том числе от разных сервисов. |
| `occurredAt`  | `OccurredAt`   | string (дата и время) | Да           | Время возникновения события в UTC, ISO 8601 с суффиксом `Z`, например `2026-11-13T07:30:00.123Z`. Это время события у отправителя.                                                                               |
| `serviceName` | `ServiceName`  | string                | Да           | Название сервиса, в котором произошло событие, например `OrdersService`. Строка не должна быть пустой или состоять из пробелов.                                                                                  |
| `level`       | `Level`        | string                | Да           | Одно из значений `LogLevel`, перечисленных ниже. Передаётся именем, с учётом регистра; числовые значения не используются.                                                                                        |
| `message`     | `Message`      | string                | Да           | Текст записи лога. Строка не должна быть пустой или состоять из пробелов.                                                                                                                                        |
| `userId`      | `UserId`       | string                | Да           | Идентификатор пользователя, с которым связано событие. Для фоновых и системных событий по этому контракту используется строка `system`. Пустая строка и `null` недопустимы.                                      |
| `metadata`    | `Metadata`     | string или null       | Нет          | Дополнительные данные в виде строки, содержащей валидный JSON. Можно опустить или передать `null`, если данных нет.                                                                                              |

### Уровни логирования

Допустимые значения `level` точно соответствуют доменному перечислению:

| Значение      | Назначение                                 |
| ------------- | ------------------------------------------ |
| `Trace`       | Самые подробные диагностические сообщения. |
| `Debug`       | Отладочная информация.                     |
| `Information` | Информация о штатной работе.               |
| `Warning`     | Предупреждение о возможной проблеме.       |
| `Error`       | Ошибка выполнения операции.                |
| `Critical`    | Критическая ошибка.                        |

### Пример сообщения

```json
{
  "eventId": "c8374480-bbb5-4dce-909e-1bfe68682e4e",
  "traceId": "d8ac45c3-9652-4e04-92bb-69ff96f4269a",
  "occurredAt": "2026-11-13T07:30:00.123Z",
  "serviceName": "OrdersService",
  "level": "Information",
  "message": "Заказ успешно создан",
  "userId": "user-123",
  "metadata": "{\"orderId\":\"order-456\",\"amount\":1500,\"currency\":\"BYN\"}"
}
```

`metadata` передаётся именно строкой с экранированным JSON, поскольку свойство
`LogItem.Metadata` имеет тип `string?`. Внутри строки в примере находится объект
`{"orderId":"order-456","amount":1500,"currency":"BYN"}`. При сохранении строка
передаётся в поле PostgreSQL типа `jsonb`. Обычный текст,
не являющийся валидным JSON, и пустая строка в `metadata` недопустимы.

Пример системного события без дополнительных данных:

```json
{
  "eventId": "a5de7686-971d-426e-8f71-d7798e9d244d",
  "traceId": "7b532848-05e1-4079-936e-f9cb0f0afc5e",
  "occurredAt": "2026-11-13T07:31:00Z",
  "serviceName": "OrdersService",
  "level": "Information",
  "message": "Фоновая обработка завершена",
  "userId": "system"
}
```

### Связь событий по `traceId`

Сервис, начинающий действие, создаёт `traceId` и передаёт его другим сервисам
вместе с запросами или сообщениями этого действия. Каждый сервис включает тот же
`traceId` в свои записи лога, но создаёт отдельный `eventId` для каждого нового
события. Для нового независимого действия создаётся новый `traceId`.
При повторной отправке одного события сохраняются оба идентификатора.

Одинаковый `traceId` у нескольких записей допустим: это ключ группировки,
а не уникальный ключ записи и не признак дубликата. Для определения повторной
доставки конкретного события используется `eventId`.
